HiFive Premier P550: installation and recovery
==============================================

Use one complete DEBUG or RELEASE package. Run host commands from its
extracted directory. Check its files with sha256sum -c SHA256SUMS.

Update SPI firmware
-------------------

Copy normal-spi.bin and SHA256SUMS to the same directory on a FAT
partition on an SD card or USB drive.
Start the board, press F2, and select Firmware Update. Select the file
and confirm the update. Wait for verification to finish before restarting.
The updater preserves UEFI variables, valid platform defaults and DDR ECC.
On the first installation of this settings format, it uses the image
records because no valid platform defaults exist yet.

USB Fastboot also supports SPI updates. Enter USB Fastboot from Boot
Manager before connecting the dual-role USB-A port to the host. Check
the target before writing:

  fastboot getvar product

The product must be SiFive HiFive Premier P550. If more than one Fastboot
device is connected, use fastboot -s SERIAL for both commands.
After confirming the target, write the image:

  fastboot flash spi normal-spi.bin

Wait for the write and verification to complete. Disconnect the download
cable, press Esc to leave Fastboot, then reset the board.

Recover when firmware does not start
------------------------------------

Use this path only when Firmware Update or USB Fastboot is unavailable.
UART loads the DDR initialization program. JTAG then starts coreboot and
UEFI from RAM. Neither step writes SPI. Update SPI from the recovered UEFI.

1. Prepare the host and identify the two serial ports.

   Debian 13's packaged OpenOCD 0.12.0 is supported:

     sudo apt install openocd minicom
     openocd --version
     sha256sum -c SHA256SUMS
     ls -l /dev/serial/by-id/

   The FT4232 provides these interfaces:

     Channel A / interface 0   EIC7700 JTAG, used by OpenOCD
     Channel B / interface 1   MCU JTAG, not used here
     Channel C / interface 2   EIC7700 serial console and UART upload
     Channel D / interface 3   MCU command console

   Use 115200 baud, 8N1, without flow control for both serial terminals.
   Do not use channel D for the DDR file upload. If more than one FT4232
   adapter is connected, disconnect the others for this procedure.
   Run only one OpenOCD process for the selected adapter.

2. Enter fresh ROM UART recovery.

   On the channel D MCU command console, run:

     bootsel-s sw 0
     bootsel-g

   Confirm software control and selector 0000 before continuing:

     sompower-s 0
     sompower-g

   Wait until sompower-g reports OFF, then run:

     sompower-s 1
     sompower-g

   Confirm that sompower-g reports ON before the UART upload.
   USB debug enumeration alone does not mean that the SoC is powered.
   A normal reboot is not a substitute for this recovery power cycle.

3. Upload DDR initialization through channel C.

   Close the channel C terminal. Keep the channel D terminal available.
   Run this from the extracted package directory, replacing the device
   path with the channel C device identified in step 1:

     sh upload-ddr.sh /dev/serial/by-id/usb-FTDI_Quad_RS232-HS-if02-port0

   The helper temporarily enables the upload flow control and restores
   the serial settings when it finishes. Wait for "Upload finished".
   The four main harts now wait for JTAG with DDR initialized.

4. Start UEFI from RAM.

   Reopen the channel C terminal so you can see the board's output.
   Run from the same package directory:

     openocd -f openocd.cfg -f load-ram.tcl -c shutdown

   The loader checks all four harts and the matching UART recovery code.
   It then loads and verifies recovery-jtag.rom in DRAM. Wait for:

     RAM image verified. Starting the UART-loaded cache handoff...
     Cache handoff verified on all four harts.
     coreboot RAM recovery started; SPI contents are unchanged

   Watch channel C for the UEFI screen. Press F2 for Setup.
   Do not issue an OpenOCD reset after DDR initialization.

5. Restore SPI boot selection and update the firmware.

   Once UEFI is running, use the channel D MCU console:

     bootsel-s hw 2
     bootsel-g

   With the SoC powered, confirm that the selector reports 0010 for SPI.
   In UEFI, open Firmware Update and select normal-spi.bin. Keep its
   SHA256SUMS beside it on the FAT drive. Wait for verification, then
   restart the board.

If recovery stops
-----------------

JTAG reports all zeroes, all ones, or cannot examine a hart:
  No RAM image has been loaded. Check SoC power with sompower-g, the debug
  cable, and channel A selection. Repeat steps 2 through 4 after a power
  cycle. Changing the firmware file does not repair an unreadable TAP.

A hart is not in fresh UART recovery, or the UART code does not match:
  Use every file from the same package. Repeat steps 2 through 4 with its
  recovery-ddr.ihex. Do not combine an older DDR upload with a new loader.

The script requests riscv exec_progbuf or reports no working memory:
  You are using an older loader. Use this package's load-ram.tcl and
  recovery-addresses.tcl. The current loader supports Debian 13 OpenOCD
  and provides the workspace needed for verification.

Newer OpenOCD prints deprecation warnings for the configuration syntax:
  The syntax is retained for compatibility with OpenOCD 0.12.0. Distinguish
  these warnings from a failed TAP scan or failed image verification.

The default JTAG clock is 1 MHz. After the default procedure works, an
optional 5 MHz command is:

  openocd -f openocd.cfg -c 'adapter speed 5000' -f load-ram.tcl -c shutdown
