HiFive Unmatched: JTAG installation and recovery
================================================

Use one complete DEBUG or RELEASE package. Run the commands below from
its extracted directory. The firmware boots through coreboot, OpenSBI
and EDK2.

Connect the board
-----------------

Connect a data cable from the host to the board's micro-USB Console port.
The onboard FT2232 provides two interfaces:

  Interface 0 / channel A   JTAG for OpenOCD
  Interface 1 / channel B   UART for the serial terminal

Power the board from its ATX supply. The USB cable powers only the debug
interface. Check that the host detects the FT2232:

  lsusb -d 0403:6010
  ls -l /dev/serial/by-id/

Open the serial device whose name contains if01. Set 115200 baud, 8 data
bits, no parity, 1 stop bit and no flow control. EDK2 uses TTYTERM with
xterm-compatible key sequences.

Use an OpenOCD build with FTDI, RISC-V, fespi and riscv smp support.
The OpenOCD 0.12.0 release lacks riscv smp. Use openocd.cfg from this
package. Run only one OpenOCD process at a time. The serial terminal
can stay open on interface 1. If USB access is denied, run OpenOCD with
sudo or configure host USB permissions.

Set the boot switches
---------------------

Disconnect board power before changing the switches. Set MSEL[3:0] to
0110 for SPI boot:

  Bit       MSEL3   MSEL2   MSEL1   MSEL0
  Value     0       1       1       0
  Switch    OFF     ON      ON      OFF

Use the MSEL labels and the SiFive guide for the board revision to locate
the switches. Leave RTCSEL and other straps unchanged. Reconnect power.
JTAG remains available when SPI is empty or contains an invalid image.

Verify the package
------------------

  sha256sum -c SHA256SUMS

Stop if a checksum fails. Use these files for the operations below:

  normal-spi.bin          8 MiB firmware image for SPI programming
  recovery-bootblock.bin  First stage for JTAG RAM recovery
  recovery-jtag.rom       Firmware image for JTAG RAM recovery
  openocd.cfg             Board and flash configuration
  prepare-ddr.tcl         Shared DDR initialization
  load-ram.tcl            RAM recovery script
  flash-spi.tcl           SPI programming script
  recovery-addresses.tcl  Build-specific DDR checkpoint

The recovery files must come from the same package. Do not program
recovery-jtag.rom into SPI.

To install firmware permanently, follow the SPI programming steps.
To test it in RAM, skip to Load firmware into RAM through JTAG.

Select the initial emulation setting
------------------------------------

The packaged image enables UEFI driver emulation. To create a copy with
emulation disabled, run:

  python3 settings.py normal-spi.bin --default-emulation disabled --output-dir noemu

Verify the copy:

  (cd noemu && sha256sum -c SHA256SUMS)

Use noemu/normal-spi.bin in both the write and verify commands below.
The tool changes only the platform setting in the copy.

After installation, use Platform Settings to change emulation. Save the
setting and restart. Restore Defaults reloads the stored defaults and
discards pending edits. Optional UEFI overrides still take priority.
See settings.md for details.

Program SPI through JTAG
------------------------

This procedure replaces the first 8 MiB of SPI, including platform
settings. UEFI variables remain at their existing location outside the
image. Saved boot entries are preserved.

Program the image from the extracted package directory:

  openocd -f openocd.cfg -c 'set fu740_image_dir [pwd]' \
    -f flash-spi.tcl -c shutdown

The script loads the recovery bootblock and waits for DDR initialization.
It programs the first 8 MiB of SPI from a DRAM work area on hart 1.
It verifies the image before restarting the board. The flash is an
IS25WP256D with a size of 32 MiB. UEFI variables outside the image remain
unchanged.

Wait for Complete SPI image verified. Keep power connected until the
script finishes. If OpenOCD reports an error, rerun this procedure before
restarting. The procedure also works when the installed image is damaged.

With MSEL[3:0]=0110, the board starts the programmed firmware. Press F2
for Setup or F12 for the boot menu. RELEASE prints fewer messages than
DEBUG.

Load firmware into RAM through JTAG
-----------------------------------

Use this procedure to test firmware without replacing the SPI image:

  openocd -f openocd.cfg \
    -c 'set fu740_image_dir .' \
    -f load-ram.tcl -c shutdown

The script resets the CPUs, loads coreboot into on-chip SRAM and waits
for DDR initialization. It then loads and verifies recovery-jtag.rom in
DRAM and starts EDK2. Confirm that the UEFI menu or prompt appears on the
serial console.

A subsequent reset discards the RAM image and attempts to boot from SPI.
SPI must contain a valid image for that boot to succeed. RAM recovery
uses the same persistent platform settings and UEFI variable store.
Changes saved through Setup therefore persist after a reset.
