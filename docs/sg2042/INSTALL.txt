SOPHGO SG2042 boot images

Use openRuyi Linux ruyi/v7.3.5-5 or a kernel with the RISC-V EFI
runtime MMIO fix and SG2042 protected-clocks support for EFI variable
services. Linux uses its native RTC driver to access the hardware clock.

Use recovery-sd.img for an initial boot from an SD card. The 64 MiB
image contains an MBR and one FAT32 partition. Verify the package first:

  sha256sum -c SHA256SUMS

Write recovery-sd.img to the whole card with a disk image writer.
This replaces its partition table and contents. Select the board's SD
boot mode. The FAT root contains fip.bin (SCP firmware) and zsbl.bin
(coreboot with OpenSBI and EDK2). The riscv64 directory contains the
three board device trees for the SCP.

To keep an existing card with an MBR and a FAT32 first partition, mount
the partition and copy the boot files and board device trees. The
commands below replace existing files with the same names. If you use a
custom SCP device tree, save it first and restore it under your board's
filename after copying. For a partition mounted at /mnt/sd, run:

  mcopy -o -i recovery-sd.img@@1048576 ::fip.bin ::zsbl.bin /mnt/sd/
  mkdir -p /mnt/sd/riscv64
  mcopy -o -i recovery-sd.img@@1048576 '::/riscv64/*.dtb' /mnt/sd/riscv64/

Unmount the partition before removing the card.

To install or update SPI firmware, copy normal-spi.bin and its matching
SHA256SUMS to a FAT filesystem. Press F2, open Firmware Update and select
the .bin file. Setup verifies its checksum and board layout. It writes and
reads back the boot files on SPI1 before committing the SCP partition table.
The update preserves UEFI variables on SPI1 and data outside those regions.
If an earlier firmware stored your settings on SPI0, record the boot order
and Setup settings before updating. Enter them again after the update.

UEFI reserves SPI1 for firmware and protects its shared AHB clock,
including on SD boots. Linux can use a separate flash connected to SPI0.
If SPI1 lacks a usable Ruyi variable partition, UEFI uses RAM variables
for that boot. Booting from SD does not install the image to SPI.
