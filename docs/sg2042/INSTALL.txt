SOPHGO SG2042 boot images

On Milk-V Pioneer, install and boot openRuyi Linux ruyi/v7.3.5-3 with
your current firmware before starting the new firmware from SD or SPI.
Other kernels need the RISC-V EFI runtime MMIO and SG2042 reserved-device
clock fixes. Older kernels can panic while probing rtc-efi.

Use recovery-sd.img for an initial boot from an SD card. The 64 MiB
image contains an MBR and one FAT32 partition. Verify the package first:

  sha256sum -c SHA256SUMS

Write recovery-sd.img to the whole card with a disk image writer.
This replaces its partition table and contents. Select the board's SD
boot mode. The FAT root contains fip.bin (SCP firmware) and zsbl.bin
(coreboot with OpenSBI, EDK2 and the three device trees).

To keep an existing card with an MBR and a FAT32 first partition, mount
that partition and copy the two boot files to its root. For example, if
the partition is mounted at /mnt/sd, run mcopy from the mtools package:

  mcopy -i recovery-sd.img@@1048576 ::fip.bin ::zsbl.bin /mnt/sd/

Unmount the partition before removing the card.

To install or update SPI firmware, copy normal-spi.bin and its matching
SHA256SUMS to a FAT filesystem. Press F2, open Firmware Update and select
the .bin file. Setup verifies its checksum and board layout. It writes and
reads back the boot files on SPI1 before committing the SCP partition table.
The update preserves the UEFI variable store, including the PlatformDefaults
variable saved by Setup, and data outside those regions.

The firmware SPI controller is reserved in the device tree passed to Linux,
including when the board boots from SD. Linux normally leaves it unbound.
UEFI also reserves SPI0 if it uses the variable partition on that controller.
Manual servicing requires exclusive access to the controller.

Both SPI controllers share an AHB clock. UEFI runtime variable access
requires that clock to stay enabled. The SG2042 clock fix keeps it on
when firmware reserves a controller that uses it.

SD boot uses persistent variables if the onboard flash contains the Ruyi
variable partition. With the original flash layout, variables stay in RAM
for that boot. Booting from SD does not install the image to SPI.
