Ruyi Firmware flashing (SpacemiT K3 Pico ITX)

The serial console uses EDK2 TTYTERM at 115200 baud, 8 data bits, no parity,
1 stop bit and no flow control. Use a terminal with xterm-compatible keys.

DEBUG and RELEASE both include UEFI driver emulation, initially enabled.
In UEFI Setup, open Platform Settings to change UEFI driver emulation.
Save the setting and restart to apply it.
The setting persists in SPI even when saved from RAM recovery.
RX6400 has been tested for UEFI/GRUB display with x64 emulation.

The platform selects AMD ARM64 GOP 1.68 for listed early GCN, Polaris
and Vega M display devices, and onboard x64 GOPs for other devices.
GCN replacement is experimental.
A failed replacement does not fall back to the onboard x64 GOP.
The serial console and native K3 display remain available.

SpacemiT vendor Linux is not supported.
Linux mainline support is provided on a best-effort basis.

Select the initial emulation setting before flashing

Verify the original package first. To disable emulation in a copy:

  sha256sum -c SHA256SUMS
  python3 settings.py normal-spi.bin --default-emulation disabled --output-dir noemu

The tool creates noemu/normal-spi.bin and its SHA256SUMS file. It changes
only the emulation configuration sector. CPU settings, UEFI variables and
executable firmware bytes stay unchanged. The original recovery-bootrom.bin
still matches the modified image. Use enabled instead of disabled to
create an enabled copy in a different output directory.

Use noemu/normal-spi.bin wherever the procedures below use normal-spi.bin.
The original package checksum does not apply to the modified image.
To check the copy, run sha256sum -c SHA256SUMS from the noemu directory.

This sets the initial SPI value. Loading Setup defaults on K3 still selects
Disabled. Saving a menu choice overrides the initial value.

First installation or migration from another firmware

Use both images from the same build. Connect the download USB-C port and
enter BootROM. Run these commands in the extracted package directory:

  sha256sum -c SHA256SUMS
  fastboot devices
  fastboot stage recovery-bootrom.bin
  fastboot continue

Wait for USB Fastboot ready:

  fastboot stage normal-spi.bin
  fastboot continue

Wait for RAM Recovery - USB Fastboot. For the first installation or when
switching from another firmware, you must flash the entire SPI NOR:

  fastboot flash spi normal-spi.bin

The spi target replaces the entire flash contents, including UEFI variables
and platform settings. The firmware target requires an existing compatible
Ruyi Firmware flash layout. Using it for a first installation or migration
can fail with:

  Writing 'firmware' FAILED (remote: 'Unsupported')
  fastboot: error: Command failed

In this case, use the flash spi command above.

After flash and verification report OKAY:

  fastboot reboot

Updating an existing Ruyi Firmware installation

Use this package's updater to apply the image's emulation setting.
Older updaters clear it instead. If the installed updater supports the new
behavior, press F9 at boot to enter USB Fastboot.

If you cannot confirm that support, enter BootROM. Run the two stage/continue
pairs in the first-installation section to load this package into RAM.
At RAM Recovery - USB Fastboot, run the commands below to preserve UEFI
variables while applying the image setting:

  sha256sum -c SHA256SUMS
  fastboot flash firmware normal-spi.bin

The firmware target preserves UEFI variables and resets CPU selection to
X100 only. This version applies the emulation setting from the new image.
It also clears DDR training records
for retraining on the next normal boot. Platform Settings saves its
selections persistently, even when the firmware was loaded into RAM.

After flash and verification report OKAY:

  fastboot reboot
